# WKR macOS Public の仕組み

## 1. 配列の正本

`wkr-layout`の配列2.0.0-beta.5（171規則）を固定commitから生成して`WKRCore`へ組み込む。配列表は[layout-reference.md](layout-reference.md)、版とハッシュは`Resources/upstream-manifest.json`を参照する。

## 2. 変換

セッションのCGEventTapで対象の物理キーだけを読み、純粋なTrie/FSTで規則を解決する。通常かなは標準ローマ字の合成キーとしてApple日本語入力へ送る。Apple日本語入力が未確定文字列・Space変換・学習を担当する。合成イベントのマーカーで再入を防ぐ。

常用はprefix-romaji。`E`でk、`E K`でき、`W E R`ではわかr、境界のEnterでわからになる。deferredはかなが決まるまで送らない。optimisticは明示確認が必要な実験方式。

`Q`は小書きの行、`P`はや・拗音の列、`W J`だけが3打鍵のゔ行へ続く。Dはた行、Fはな行、Uは促音「っ」、Nは「いぇ」・ぇ列、Mは「ん」。v2では専用の記号・矢印・短縮列を持たず、通常のかな規則はすべてローマ字で送る。

## 3. 安全に停止する

実際の入力ソースIDとモードIDの両方が対象と一致し、権限・event tap・前面アプリ・Secure Event Inputの条件がすべて成立するときだけ変換する。メニュー操作と手動一時停止はゲートを閉じる。入力ソース変更・マウス・カーソル移動・アプリ切替等で保留を破棄し、別の入力へ持ち越さない。

権限取消し、tap無効化、合成出力失敗では状態を捨て、同じtapを自動で復活させない。通常は終了し、起動し直したときに条件を再確認する。Secure Event Input中は通常入力へ通し、解除後に再照合する。入力ソースを自動選択しない。

メニューの「変換中」は、入力権限と稼働tapの準備が済んだ状態だけを表します。未許可では権限待ち、tap未開始では未開始を表示し、メニューを開いても変換中へ変わりません。見出し・詳細・対処を同じ状態から更新します。

### 起動時だけの回復

初回に権限が不足している場合は案内ウインドウを維持する。3秒間隔・既定300秒の有限な再確認だけを同じプロセスで行い、許可ダイアログを自動で重ねない。上限後も利用者は案内の「状態を再確認して変換を開始」を選べる。

権限が許可済みでもtapの作成を断られた場合、または実際のkeyDown / keyUpをまだ一つも受け取る前にtimeoutでtapが無効化された場合だけ、3秒後に新しいプロセスで再試行する。初回失敗から既定300秒で諦め、前のプロセスの終了・排他状態・権限・現在の入力ソースを毎回確認する。後継はUI・状態表示を準備して起動処理から戻った後、main threadを塞がないtimerで最長5秒だけ前の終了を確認し、生存中は変換を開始しない。前プロセスの終了待ちが5秒の期限に達した場合は手動再確認の案内に留まる。起動再試行自体の待機上限に達した場合は終了する。キーを一つでも受け取った後のtimeout、利用者操作によるtap無効化、権限取消し、合成出力失敗はこの再試行に含めない。

メニュー、監視通知、安全timerと初期コンテキストを準備してから最後にtapを開始する。再試行の状態は一時的な起動引数だけで渡し、ファイルや設定へ保存しない。詳細と設定は[install.md](install.md)を参照する。

Public / 新Privateの排他契約と旧版との切替制限は[migration.md](migration.md)を参照する。

## 4. 英字への打ち直し

英数を短時間に2回押すと、現在の未確定範囲だけを打った英字へ戻す。最大12打鍵・短い寿命のメモリ内履歴を使い、境界で破棄する。ファイル・ログへキー列を出さない。句読点をまたぐ削除は行わない。

## 5. 日別頻度

明示的に有効化した場合だけ（キーコード、Shift）→回数、暦日、配列IDを保存する。対象外入力源・Secure Event Input・権限不足・除外中・一時停止中は数えない。かな/英数の切替キーだけは入力源一致を除く同じ安全条件で数える。

callbackはメモリ内加算だけ。120秒ごとに値を取り出し、専用serial queueで既存値とのマージ・保持期間・0600書出しを行う。終了時はtap停止後に未保存分を処理する。失敗分はメモリに残し、次回へ持ち越す。

図は論理キー合計のJIS / US / Cornix表現で、実打鍵元や同じ論理キーを送る複数の物理位置を識別しない。実キーマップは利用者のローカルファイルだけを参照する。機器接続の取得・分類はこの版に含めない。

## 6. 練習

同梱ページを非永続WKWebViewで開く。ブラウザ版と同じ教材・採点処理を使い、HTTP(S)をブロックする。システム変換を持たないキー位置練習と、確定したひらがなを比較する日本語入力練習がある。

Native橋渡しは同梱のメインフレームからのload / save / deleteだけ。保存は課題ID・完了回数・最高正答率・配列版の許可リストへ作り直し、誤入力やキー列を保存しない。保存I/Oは入力監視のrun loop外で行う。練習結果を日別頻度や研究計測へ送り込む連携はない。

## v1・v2・練習帳のビルド構成

WKRV1とWKRPublicは同じWKRCoreのWKRTransducerとWKRMacOSの権限・停止・排他処理を使います。WKR_BUILD_FLAVORでコンパイル時に規則表と製品IDを選びます。v1規則とキートップは公開済み保存ソースから固定し、v2規則・全練習教材はwkr-layoutのcommitから生成・取り込みます。規則の差を実行時の切替では吸収しません。

WakaraPracticeは別実行ターゲットでWKRPracticeUIを使い、WKRMacOSへ依存しません。WKWebViewの通信遮断・同梱教材の読取・集約した成績の保存だけを共有します。ページ内のQWERTY体験ではengine.jsが171規則を使い、WKR・IMEモードでは確定文字列を採点します。実IMEでの未確定文字列やmacOSの合成キー出力を再現するものではありません。
