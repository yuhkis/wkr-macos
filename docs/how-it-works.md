# WKR macOS Public の仕組み

## 1. 配列の正本

`wkr-layout`の配列2.0.0-beta.1（233規則）を固定commitから生成して`WKRCore`へ組み込む。配列表は[layout-reference.md](layout-reference.md)、版とハッシュは`Resources/upstream-manifest.json`を参照する。

## 2. 変換

セッションのCGEventTapで対象の物理キーだけを読み、純粋なTrie/FSTで規則を解決する。通常かなは標準ローマ字の合成キーとしてApple日本語入力へ送る。Apple日本語入力が未確定文字列・Space変換・学習を担当する。合成イベントのマーカーで再入を防ぐ。

常用はprefix-romaji。`E`でk、`E K`でき、`W E R`ではわかr、境界のEnterでわからになる。deferredはかなが決まるまで送らない。optimisticは明示確認が必要な実験方式。

`Q`は小書きの行、`P`は特殊・記号、`W J`だけが3打鍵のゔ行へ続く。`/`は疑問符、Shift+/は中点。Unicode記号は確定文字になり、未確定文字列の途中では抑止する。P記号層を無効にしても、ローマ字で出す矢印と行キー後の特殊列は残る。

## 3. 安全に停止する

実際の入力ソースIDとモードIDの両方が対象と一致し、権限・event tap・前面アプリ・Secure Event Inputの条件がすべて成立するときだけ変換する。メニュー操作と手動一時停止はゲートを閉じる。入力ソース変更・マウス・カーソル移動・アプリ切替等で保留を破棄し、別の入力へ持ち越さない。

権限取消し、tap無効化、合成出力失敗では自動でtapを復活させず終了する。起動し直したときに条件を再確認する。Secure Event Input中は通常入力へ通し、解除後に再照合する。入力ソースを自動選択しない。

Public / 新Privateの排他契約と旧版との切替制限は[migration.md](migration.md)を参照する。

## 4. 英字への打ち直し

英数を短時間に2回押すと、現在の未確定範囲だけを打った英字へ戻す。最大12打鍵・短い寿命のメモリ内履歴を使い、境界で破棄する。ファイル・ログへキー列を出さない。句読点をまたぐ削除は行わない。

## 5. 日別頻度

明示的に有効化した場合だけ（キーコード、Shift）→回数、暦日、配列IDを保存する。対象外入力源・Secure Event Input・権限不足・除外中・一時停止中は数えない。かな/英数の切替キーだけは入力源一致を除く同じ安全条件で数える。

callbackはメモリ内加算だけ。120秒ごとに値を取り出し、専用serial queueで既存値とのマージ・保持期間・0600書出しを行う。終了時はtap停止後に未保存分を処理する。失敗分はメモリに残し、次回へ持ち越す。

図は論理キー合計のJIS / US / Cornix表現で、実打鍵元や同じ論理キーを送る複数の物理位置を識別しない。実キーマップは利用者のローカルファイルだけを参照する。機器接続の取得・分類はこの版に含めない。

## 6. 練習

同梱ページを非永続WKWebViewで開く。ブラウザ版と同じ教材・採点処理を使い、HTTP(S)をブロックする。システム変換を持たないキー位置練習と、確定したひらがなを比較する日本語入力練習がある。

Native橋渡しは同梱のメインフレームからのload / save / deleteだけ。保存は課題ID・完了回数・最高正答率・配列版の許可リストへ作り直し、誤入力やキー列を保存しない。保存I/Oは入力監視のrun loop外で行う。練習結果を日別頻度や研究計測へ送り込む連携はない。
