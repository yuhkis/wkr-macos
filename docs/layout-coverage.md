# かなの網羅状況

**「Apple日本語入力のローマ字入力で打てるかな」と「わから配列で打てるかな」を突き合わせた結果**を
まとめます。配列表そのものは [layout-reference.md](./layout-reference.md)、採否の根拠は
[design.md](./design.md) にあります。

比較の基準は Apple日本語入力のローマ字表
（`CoreJapaneseEngine.framework` の `RomajiRule_Default.txt`、447行）です。ここから
かなだけを出力する規則を取り出すと **206種**になります。これが「素のローマ字入力で
直接打てるかな」の全体です。2026-08-16 に照合しました。

## 結論

| 分類 | 2026-08-16 の変更前 | 変更後 |
| --- | ---: | ---: |
| 配列に専用規則がある | 136 | **138** |
| 専用規則はないが、基本かな＋前置小書きで作れる | 61 | **68** |
| **どちらでも作れない** | **9** | **0** |

**打てないかなは無くなりました。** 内訳と対応は次のとおりです。

| かな | 原因 | 対応 |
| --- | --- | --- |
| ゔ ゔぁ ゔぃ ゔぇ ゔぉ ゔゃ ゔゅ ゔょ | `WJ → ヴ` が Unicode 直接注入で、その場で確定して未確定文字列から出ていた。後ろに小書きを繋げられない | `WJ` の出力を `ゔ`（ローマ字 `vu`）へ変更。未確定に残るので8種すべてが小書きとの組み合わせで作れるようになった |
| ヵ | ひらがなの形がないので基本かな＋小書きでは作れず、配列にキーもなかった（`ヶ` は `EY` にあった） | `QY → ヵ`（ローマ字 `lka`）を追加。が行の `Y` スロットが空いていた |

## なぜ `ヴ` だけ特別だったのか

Apple日本語入力のローマ字表で**カタカナを出す規則は5件だけ**です。

```
-  ->  ー      lka -> ヵ      lke -> ヶ      xka -> ヵ      xke -> ヶ
```

`ヵ` `ヶ` にはひらがなの形がないため、表が直接カタカナを返すしかありません。一方 `ヴ` には
ひらがなの `ゔ`（U+3094）があるので、`v` で始まる12件の規則はすべて `ゔ` 系を返します。

```
vu -> ゔ    va -> ゔぁ    vi -> ゔぃ    ve -> ゔぇ    vo -> ゔぉ    vya -> ゔゃ  …
```

**ひらがなモードでカタカナの `ヴ` を直接出す綴りは存在しません。** 素のローマ字入力でも
`ゔぁいおりん` と打って Space で `ヴァイオリン` にするのが正規の経路です。

上流 `wkr-layout` は `WJ` のかなを `ヴ` と定めていますが、wkr-macos は `ゔ` を出します。
**これは綴りの違いではなく、かな自体の差分です。** [layout-reference.md](./layout-reference.md)
の「かなは上流と同一」という宣言に対する唯一の例外で、上流 v1.1 への反映が要ります。

## 要検討（上流 wkr-layout の判断）

### 1. `ゔ` 行に専用規則を置くか

いまは `WJ` の後に前置小書きを打つ4打鍵です。`ゔぁ` は外来語で頻出するので、専用規則を
置く価値があるかもしれません。ただし **`W` 行の変種スロットはすべて埋まっています**
（`H`=わ、`K`=うぃ、`J`=ゔ、`;`=うぇ、`L`=を、`U`=ゐ、`I`=ゑ、`O`=うぉ、`Y`=ゎ）。
置くなら別の行か、3打鍵目を使う新しい形が要ります。

### 2. `て` / `で` 系の非対称

`X` 行に `てぃ`（`XU`）`てゅ`（`XY`）`でぃ`（`XO`）`でゅ`（`XI`）はありますが、
**`てゃ` `てょ` `でゃ` `でょ` はありません。** `ゔ` 行と同じく、外来語表記の穴として
まとめて検討するのが自然です。

### 3. 後置小書きの残り7件

`KT → ぃ` は 2026-08-16 に削除しました。`K` の後の `T` がこの規則に吸われ、
`K` `T` `;` が `いぇ` ではなく **`ぃえ`** になっていたためです。

**同じ衝突が残り7件にもあります。**

| 後置小書き | 潰している入力 |
| --- | --- |
| `HT → ぁ` | `H` + 前置小書き（`あぁ` `あぃ` …） |
| `JT → ぅ` | `J` + 前置小書き |
| `;T → ぇ` | `;` + 前置小書き |
| `LT → ぉ` | `L` + 前置小書き |
| `UT → ゃ` | `U` + 前置小書き |
| `IT → ゅ` | `I` + 前置小書き |
| `OT → ょ` | `O` + 前置小書き |

潰れる組み合わせはいずれも実用頻度が低く、`KT` のように「`いぇ` が打てない」という
はっきりした害は見つかっていません。後置小書き自体は前置形より打ちやすい場面があるので、
**一律に廃止するかどうかは上流の判断**とします。後置形にはもう1つ、先に出した母音1かなを
置き換えるためのちらつきという既知の欠点もあります（[design.md](./design.md) 5.3）。

### 4. `T,` `T.` `T/` は Unicode のまま

`，` `．` `／` は全角約物で、ローマ字表に綴りがありません。未確定文字列があるときは
入力されず、ログに残ります（[design.md](./design.md) 5.4）。`,` `.` `/` を直接打てば
ことえりの句読点設定に応じた文字が入ります。

## 再現手順

比較は次の2つを突き合わせています。

- Apple日本語入力のローマ字表:
  `/System/Library/PrivateFrameworks/CoreJapaneseEngine.framework/Versions/A/Resources/RomajiRule_Default.txt`
- `WKRLayout.rules`（222件）

「作れる」の判定は、**基本かな1文字＋小書き1文字に分解できるか**で行っています。
`つぁ` = `つ` + `ぁ` のように、送るローマ字が違っても未確定文字列の文字列は同一になります。

**この判定は打鍵列の衝突までは見ていません。** `いぇ` は構造上ずっと「作れる」側でしたが、
`KT → ぃ` が `K` の次の `T` を吸っていたため実際には打てませんでした。同種の衝突が
残っていないかは、上の「後置小書きの残り7件」で個別に見ています。
