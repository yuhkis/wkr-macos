## 1. 仮想マシンでの入力モード同期

**状況**: WKR の合成イベントは Parallels のゲスト（Windows）へ届くことを 2026-08-13 に実機確認済み。
ゲスト側の IME が標準ローマ字を変換するので、**ゲストにわから配列を入れる必要がない**ことが
分かっている。

**未解決**: 日本語／英語の切り替えに、macOS の入力ソースとゲストの IME という**2つのスイッチ**を
揃える必要がある。理想は1打鍵で両方が切り替わること。

**分かっていること**:

- Mac の かな / 英数 は HID の `LANG1` / `LANG2` を送る。Windows の IME が反応するのは
  `変換` / `無変換`（`INT4` / `INT5`）と `半角/全角` で、**Windows は LANG1/LANG2 を標準では解釈しない**。
- WKR は かな / 英数 を横取りせず前面アプリへ渡すので、WKR 側の変更なしでゲストへ到達する。
- 未知のキーコードは境界キー扱い（保留中のかなを確定して素通し）なので、`INT4` / `INT5` が
  流れても WKR は壊れない。

**候補A（まず試す）— QMK/Vial 側で1キー2役にする**

キーボードがプログラマブルなので、macOS 用と Windows 用を同時に送る。

```
Macro 0:  Tap KC_LANG1 → Tap KC_INT4     日本語ON
Macro 1:  Tap KC_LANG2 → Tap KC_INT5     日本語OFF
```

Windows 側は MS-IME の「キーとタッチのカスタマイズ」で
`無変換キー → IME-オフ` / `変換キー → IME-オン` を設定する。

制約: `LT()` のタップ側にマクロは置けないため、Layer 0 左親指内側の `LT2(KC_LANG2)` を
そのままマクロ化することはできない。`MO(2)` に変えてレイヤー2側で打つ形に組み替える必要がある。

**確認事項**: macOS が `KC_INT4` / `KC_INT5` に反応して余計な文字を出さないこと。
TextEdit で打って何も出なければ候補Aで確定。

**候補B（Aに副作用がある場合）— WKR 側で送る**

`--vm-app <bundleID>` のようなオプションを追加し、**指定アプリが前面のときだけ**
かな → `変換`、英数 → `無変換` を追加送出する。前面アプリの判定は `--exclude-app` の実装で
既にあるので、追加は小さい。ただし WKR に状態依存の機能が増えるため、候補Aで済むならそちらを優先する。

## 5. Control 付きショートカットでの保留の扱い

**2026-08-16 にかな完成を実装し、2026-08-23 にローマ字変換を分離した。**
`W` `E` `R` の後に Ctrl+K を押すと `ワカラ` ではなく `ワカr` に
なっていた。Control 付きのキーが `reset(.modifiedKey)` で状態を捨てて素通ししていたため、
保留していた `a` が送られず `r` が未確定に取り残されていた。

Apple日本語入力のControlショートカットは、**どの英字が何をするかがキー設定で変わる**。
今回報告された割当てではCtrl+J / Ctrl+Kをかな変換として保留中のかなを先に確定し、
Ctrl+L / Ctrl+;をローマ字変換として末尾母音を補わず仮ローマ字までを変換させる。
Shift併用とほかのControlは従来どおりかな完成側へ倒す。複数設定の既知ショートカットを和集合にすると、
選択されていない設定では別操作を誤分類するため、設定を識別できるまでは追加しない。
Command と Option は従来どおり破棄して素通しする（フォーカスを移し得るため）。

**自動確認済み**: prefix / deferred / optimistic の3方式で、ローマ字変換が末尾に `a` を追加せず、
仮ローマ字の状態で原キーを通すこと。変換後もUnicode注入ゲートが未確定文字列ありの判定を
保守的に維持すること。

**TextEdit / prefixで実機確認済み（2026-08-24）**: Ctrl+Jは `わから`、Ctrl+Kは
`ワカラ`、Ctrl+Lは `ｗａｋａｒ`、Ctrl+;は `wakar` となり、ローマ字変換側で末尾の
`a` を補わないことを確認した。

**未了**: deferred / optimisticモード、Notes / Safari、ほかのキー設定を安全に識別する方法、
同じ問題が残るF9 / F10、ターミナルや Emacs で保留中に Ctrl+C などを押した場合の副作用。

## 8. 英字への打ち直し

日本語入力モードのまま英単語を打ったとき、`英数` 連打の読み戻しが物理キー列ではなく
WKR が送った合成ローマ字を返す（`T` `H` `I` `N` `G` → `layunnh`）。方式に由来する限界で、
WKR が未確定スコープの物理キー列を保持しない限り復元できない。

設計は [design.md](./design.md) の「8. 英字への打ち直し」にある。

**実装済み**: `WKRCore` の `EnglishFallbackJournal` と、`EventTapController` での記録・発動。
既定のトリガは `英数` の連打が終わったとき。`--english-fallback` とユーザーデフォルト
`EnglishFallbackTrigger` で変更できる。使い方は [install.md](./install.md)。

**確認済み**: 2026-08-15、TextEdit と Claude.app で連打方式・コード方式とも置き換えが成立した
（[verification.md](./verification.md)）。

先行するテキストを置いた状態でも、削られたのは送出済みローマ字だけだった（`ABCDEFGHIJthing`）。

2026-08-16 に対象範囲を広げた。矢印4件がローマ字になり、取り消しを伴う66件も削除文字数を
数えるようにしたので、`EY` `WY` は `eywy` へ戻せる。Unicode 出力を通った場合だけ発動しない。

**未了**: 連打の間隔が Apple日本語入力の2回押し判定とずれた場合の挙動。読み戻しに必要な押下回数が
何によって変わるのかも未確認（連打方式は回数を数えないので動作は変わらない）。
Notes、Safari、Slack など他アプリでの確認。

**未実装**: 設定ウィンドウ。値の置き場所はユーザーデフォルトに用意済みなので、上の
「2. メニューバー表示」を作るときに束ねる。

## 9. 打鍵頻度とヒートマップの残件

2026-08-27に実装、2026-08-28に実機トライアル済み（120秒タイマー flush・矢印・修飾キー・
パスワード欄の不計数まで確認）。確認範囲は [verification.md](./verification.md) にある。

- **`--key-frequency-retention` を指定したときの切り捨ての実測。** 既定は無制限保持に
  変えたため、窓を指定した場合の経路が未確認のまま残る（終了時 flush と日またぎは
  2026-08-29に実測済み）。
- **修飾キー計数の残り。** 左右同時押しが1回になること、Caps Lock が点灯側だけ数えられる
  ことは未実測（押下エッジの基本動作は確認済み）。
- **期間の比較ビュー。** いまは1つの期間を描くだけで、「配列を変えた前後」を並べて比べられない。
  日別バケットは持っているので、2つの期間の差分を描く余地はある。
- **メニューバーからレポートを開く導線**（2節と合わせて検討）。いまはCLIか `make` から起動する。
- **`.vil` の高位レイヤー。** レイヤー0だけを描いている。集計は macOS のキーコードしか持たず、
  どのレイヤー経由で届いたかを知らないため、高位レイヤーを描いても数値を対応づけられない。
  対応づけるならファームウェア側から情報を出す必要があり、このアプリの観測点の外になる。
